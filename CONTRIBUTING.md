# Guide de contribution

Merci de votre intérêt pour splitUL !

Même une petite contribution peut propulser un projet : code, documentation, suggestions, tests, rapporter un bug, etc..

Ce guide vous aidera à débuter votre contribution.

---

## Avant de commencer

- Assurez-vous d'avoir lu le fichier [README.md](./README.md).
- Vérifiez s’il existe déjà une *issue* similaire à votre contribution.
- Pour des changements majeurs, ouvrez une *issue* pour en discuter d’abord.

---

## Comment contribuer

1. **Fork** le dépôt
2. Créez une branche (`git checkout -b feature/nom-de-votre-fonctionnalité`)
3. Apportez vos modifications
4. Assurez-vous que le code passe les tests (`npm run test`)
5. Faites un commit clair (`git commit -m "[#Issue] - Ajout de [fonctionnalité]"`)
6. Poussez la branche (`git push origin feature/nom-de-votre-fonctionnalité`)
7. Ouvrez une **Pull Request**

---

## Bonnes pratiques

- Respectez les conventions de codage du projet.
- Utilisez des messages de *commit* explicites.
- Testez votre code avant de soumettre.
- Rédigez ou mettez à jour la documentation si nécessaire.
- Soyez courtois et constructif dans vos échanges.
